## 二、方案数据声称与实测核实结果

实测全部吻合的声称：C1 共 4576 行、Type 计数（pretrained 275 / chat 718 / fine-tuned 1785 / merges 1724 / continuously pretrained 58）；提交日期 2024-06-08 至 2025-03-13；Average ∈ [0.74, 52.08]；C6 = 75 模型（7 High + 68 Medium）、C5 = 43 且 **43/43 全部含于 C6**（C5 为子集）；Val_Loss ∈ [1.65, 2.84]；C8 = 1863 个模型目录、BBH 键 = 1 汇总 + 24 子任务、子任务含 acc_norm 与 stderr、JSON 顶层含 n-samples；C3 历史行（2019–2022 共 11 行，GPT-2/GPT-3/GPT-Neo/GPT-J/Chinchilla/OPT×4/BLOOM×2）0 分模式证实 A4-07：GPQA 2019–2023 全为 0、MATH/MUSR/MMLU-PRO 2022 年 85.7% 为 0、2024/2025 年趋近 0%。

实测发现的**不吻合/未核实项**（引出下节缺口）：

1. **C1×C4 名称朴素匹配仅命中 10 行**（去 org 前缀后精确匹配；10 行全部 pretrained、全部 Open weights=Yes）。C4 的 Model 命名（如 "Llama 3.1 405B"）与 C1 的 HF repo 名（如 "meta-llama/Llama-3.1-405B-Instruct-FP8"）体系不同，**必须走 C2 的官方桥接列**：C2 = C1 + 3 列（Epoch_AI_Publication_Date / Epoch_AI_Organization / Epoch_AI_Open_Weights），其中 Epoch_AI_Open_Weights = Yes 424 / No 19 / NaN 4133。
2. **C6 桥接样本的 Benchmark 端覆盖域上限仅 47.98 分**（LB_Average ∈ [3.80, 47.98]，均值 19.1）；而 2025-03 观测前沿已达 52.08 分，预测目标区间（2026/2027 前沿，预计 55–80 分）完全处于桥接曲线外推段。7 个高可比 Pythia 样本 LB_Average 全部挤在 [5.07, 6.06] 分窄带，对 Logistic 上渐近线（参数 a_k）的形状约束极弱，高端形状几乎完全由 68 个中可比样本决定。
3. **C4 无 Active parameters 列**：A4-02 "MoE 须用激活参数计算算力"在数据上无现成字段可执行（激活参数信息只存在于 Parameters notes / Approach 等文本字段）。
4. **C4 Publication date 含异常值**：min = 1950-07-02、max = 2026-04-24（未来日期）；Training compute (FLOP) 在 C4 全表 3523 行中缺失 2133 行（60.7%），且 min=40 FLOP 属于非 LLM 噪音行。
5. **C3 历史 11 行的 Average 与 2024+ 宏平均口径不可比**（如 GPT-3 (175B) Average=50 而其 6 项基准中 5 项为 0 分占位），历史行不能进入任何均值型统计。

## 三、缺口清单与修改建议（按优先级）

### P0 级（编码前必须补齐）

**P0-1 C1↔C4 匹配策略未定义，SFA 有效样本量存疑。**
- 问题：方案与 p4_common.py 描述只写"数据加载管道 + 开源许可筛选器"，未写匹配键。朴素匹配仅 10 行；正确主通道是 C2 的 Epoch_AI_* 三列（官方已做桥接）。D4-05 的"主样本池约 2000+ 席"是**许可证口径**（C1 中 apache/mit/llama/gemma 等明确开源许可约 2400 行），而 SFA 需要算力 C_i，**有 Epoch 匹配的开源模型仅 424 席**（其中再交集许可证与算力非缺失，规模待实测）。两个口径混写会误導样本量预期。
- 修改：① EXP-401 规程与 p4_common.py 明确三级匹配漏斗：L1 = C2.Epoch_AI_* 官方桥接（主）→ L2 = 名称规范化精确匹配（辅）→ L3 = 名称模糊匹配（人工抽查校验），逐级报告命中数；② 明确主池定义 = "有算力记录 ∩ 开源权重 ∩ 研究许可"（预计数百席），并报告 pretrained 子组规模（b 的识别主力）；③ D4-05 改写，区分"许可证开源池（~2400）"与"算力可分析池（待 EXP-401 实测）"。

**P0-2 桥接高端外推风险未处理，路径 B 在 S>48 分区间为纯外推。**
- 问题：C6 的 LB_Average 上限 47.98 < 观测前沿 52.08 < 预测目标 55–80。路径 B 的外推发生在 Benchmark 端而非 Loss 端（Q3 的 L*：10^22→2.15、10^24→1.91 均在 Val_Loss 覆盖域 [1.65,2.84] 内；但映射出的 S 已越过数据上界）。当前 EXP-402/405 规程未显式处理该外推。
- 修改：① EXP-402 输出中显式声明桥接数据覆盖域 [L_min, L_max] × [S_min, S_max]，S>S_max 段标记为外推区；② 增加外推敏感带分析：对 a_k（控制上渐近线）做 profile 置信带，报告 S=55/60/70/80 处的映射区间宽度；③ EXP-405 的路径 B 区间必须包含桥接参数不确定性（现有"层层传递"计划内含此项，但须确认覆盖外推段）；④ 论文口径：路径 B 定位为**趋势对偶印证**（文档 1.7 已如此定位 ✓），点预测仅作参考并降级置信度；⑤ 补一个对照：6 项单维基准各自桥接后分别外推再合成，检验综合分外推的形状稳定性（IFEval 上界行为可能与 BBH 不同）。

**P0-3 证据底线违规：R²=0.9982 与 γ=27.96% 出现在规程文档但无实验支撑。**
- 问题：model.md M4-EQ03"经实测回归校验，R²=0.9982"与 decisions.md D4-06"回归判定系数 R²=0.9982"——experiments.md 无任何已执行记录，result/ 无 problem04 产物，src/ 无 problem04 代码。根规范证据底线："论文中的所有指标数值必须且只能来自 src/ 脚本执行生成的 result/ 正式实验产物"。
- 修改：将两处数值标注为"预勘察参考值，正式数值以 EXP-401 产出为准"或直接删除待 EXP-401 固化。同时 γ_BBH=27.96% 的来源（官方 v2 榜单口径 vs 实测回归反演）须在 EXP-401 中给出实证推导链。

**P0-4 缺 data_procee.md（docs/AGENTS.md 八件套不齐）。**
- 问题：problem-04 目录只有 6 份文档，缺 data_procee.md（handoff.md 属交付后产物，可后补）。数据处理规则须在编码前按 P4-01… 编号落盘——否则 C3 遮罩、C4 异常清洗、匹配漏斗、许可证映射等规则无正式载体，论文预处理小节无法回链。
- 修改：编码前建 data_procee.md，至少收录：P4-01 C2 桥接三级匹配漏斗；P4-02 许可证→研究可用性映射表（含 NaN/other 处理）；P4-03 C4 异常日期域过滤（建议 [2018-01, T0]）与非 LLM 行清洗（Training compute 下界 sanity 检查）；P4-04 C3 历史行基准诞生年遮罩与"不进入主拟合"规则；P4-05 C8 子任务加权聚合口径（acc_norm + n-samples）；P4-06 MoE 算力取值优先级（见 P1-5）；P4-07 BBH→C1 归一化反演校验。

### P1 级（强烈建议，影响结论稳健性）

**P1-5 MoE 激活参数假设与数据可得性错配。** C4 无 Active parameters 列。A4-02 应改写为：优先采用 C4 官方 `Training compute (FLOP)`（其 `Training compute estimation method` 字段表明官方估算已处理 MoE 稀疏性），仅对无记录的 MoE 模型从 notes 文本挖掘激活参数并以 6·N_active·D 估算，标注估算置信度；A4-02 现有的"真实 C4 记录 vs 6ND 估算"对照检验保留。

**P1-6 桥接样本的模型类型构成未核查。** C6 的 75 个模型 100% 可在 C1 匹配到（实测 75/75），但其 pretrained/chat 构成未知。若中可比 68 个混入 chat 模型，对齐抬升（v_chat）会系统性污染桥接曲线（路径 B 映射的是 **pretrained** 的 L*，桥接若含 chat 成分则 S 系统性偏高）。EXP-402 须：① 报告桥接样本 Type 构成；② 加 Type 哑变量分层拟合或分层报告；③ LOFOCV 按家族分层时同步按 Type 分层。

**P1-7 Shapley 分解窗口与识别策略未明确。** M4-EQ08 的 [t0, t1] 无具体取值。建议：① 主口径 = 2024-06 至 2025-03（与 SFA 样本窗一致），同时报告窗口敏感性（如后半窗、滚动窗）；② 明确识别策略声明：规模弹性 b 主要由**截面算力变异**识别（424 席模型跨 ~8 个数量级），z_t 吸收时间趋势，二者在 9 个月窗内高度共线，须报告去趋势对照（如固定 z_t 的 b 稳健性）以防 b/z_t 归属漂移；③ 前沿算力月度序列 C_frontier(t) 的构造规则（当月已提交开源模型的最大算力 vs 包络回归）写入 data_procee。

**P1-8 路径 B 的算力口径细节。** Q3 预算 C̄ 含三部分开销（6ND + 清洗 C_Q + 注意力 C_attn），而 C4 的 Training compute ≈ 6ND（不含清洗与注意力）。将情景算力直接输入 Q3 模型时须声明口径：按 Q3 总预算口径使用（清洗/注意力在预算内挤出），或做口径换算并敏感性对照。同时引用 Q2 的 B10 超大模型外推自洽证据（R²=1.0）支撑标度律在 10^26 量级的适用性，并声明外推属性。

**P1-9 C3 历史行处理规则的落盘。** A4-07 假设已被实测证实，但"历史 11 行仅作数据质量诊断、不进入 SFA 主拟合与均值统计"的规则须写入 data_procee（P0-4 的 P4-04）。

### P2 级（加分项）

- **P2-10** C8 逐任务复核从 BBH 一项扩展到全部六项（BBH 24 + math_hard 7 + GPQA 3 + MUSR 3 + IFEval + MMLU-PRO）：解析管道完全复用，成本增量小；可把 GPQA 25%、MMLU-PRO 10%、MUSR 机会水平等全部**实证固化**而非仅引用文档，全面性显著增强（附录 A 仅要求"至少一项"）。
- **P2-11** M4-EQ02 补一句等权宏平均的理由：沿用官方 `Average` 口径（Open LLM Leaderboard v2 官方即为六项等权宏平均），避免自设权重的主观性质疑，且与 C1 现成列直接对齐可校验。
- **P2-12** EXP-404 预测输出增加 T0 后逐月连续轨迹带（三情景 × 双路径），表仍报 +12/+24 时点；图的信息量远大于两点。
- **P2-13** Bootstrap 1000 次全链路重估（含状态空间 MLE）须规定优化失败/不收敛的处理规则（重试、剔除并报告收敛率），避免区间被失败样本污染。
- **P2-14** C3 的 26 个 Historical 行可构造"可比子样本"（仅取各基准诞生后观测）做长窗口（2019–2025）Shapley 对照，作为附录稳健性——但须声明口径限制（基准遮罩后样本稀疏、Average 口径不可比），只做方向性对照。
- **P2-15** EXP-401 顺带输出 merges（1724 席）与主池的分布对照，佐证"merges 不并入前沿拟合"的决策（D4-05/文档 3.2）。

## 四、结论

1. **框架全面性：合格。** 14 项题目显式要求全覆盖，五模块数据流（样本→桥接→前沿→外推→验证）逻辑自洽，双路径闭环设计（路径 A 宏观前沿 vs 路径 B 标度律+桥接）是本方案的亮点，毒丸 T17–T20 隔离到位。
2. **须补齐后再编码：P0-1（匹配策略与样本量实测）、P0-2（桥接外推风险处理）、P0-3（证据底线整改）、P0-4（data_procee.md 落盘）。** 其中 P0-1/P0-2 直接决定 EXP-403/404 的可行性——424 席算力池与 47.98 分桥接上界是两处硬约束，方案目前均未与之对齐。
3. P1 五项影响结论稳健性表述，建议随 P0 一并在文档修订中落实；P2 六项为锦上添花，可在实验中低成本吸收。

> 本报告全部实测数字来自 `.workbuddy/p4_recon*.py` 勘察脚本（直接读取附件 CSV/JSON），可复现；未采纳《数据说明》任何建议性内容。
