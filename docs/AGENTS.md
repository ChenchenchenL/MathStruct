
# 数学建模与编码记录规范

本文件仅约束 `docs/` 目录内的工作。目标是为数学建模和编码求解过程建立可追溯记录，使后续论文写作者能够依据记录复述问题、模型、数据、实验和结论。论文优秀范例只用于判断哪些信息值得保存；不要为了模仿论文格式记录与当前题目无关的内容。题目数量、子问题数量和模型类型均不固定。

## 核心原则

- **先记录后求解**：在运行大规模实验或修改模型前，先写明数据版本、假设、公式版本和代码入口。
- **公式可复述**：每个实际使用的公式都必须给出变量定义、单位、适用条件、参数来源和代码实现位置。
- **数据可追溯**：每个输入字段都要能追溯到原始文件、工作表/列、采集时间或题目附件，并记录清洗、筛选、插补和聚合操作。
- **单位不省略**：数值、参数、阈值、坐标、时间、速度、质量、能量、概率和误差均记录单位；无量纲量明确写“无量纲”。
- **结果可复现**：记录运行命令或入口、环境、随机种子、参数配置、输出文件和评价指标。
- **结论与证据绑定**：任何用于论文的结论都必须链接到对应数据表、图、公式、日志或代码提交。
- **区分事实与假设**：题目直接给定的数据/条件、外部资料、建模假设、拟合结果和主观判断必须分开标注。

## 推荐文档结构

每道题或每个独立子问题在 `docs/` 下建立一个目录。题目数量不固定，可采用 `problem-01/`、`problem-02/` 等名称；不要假设固定的题号或章节数。建议结构如下：

```text
docs/
  AGENTS.md
  problem-XX/
    README.md                 # 问题范围、当前状态、文件索引
    assumptions.md            # 建模假设与适用边界
    data-dictionary.md        # 字段、单位、来源、质量检查
    model.md                  # 公式、符号、参数与模型版本
    data_procee.md            # 数据处理规则：按执行顺序编号记录，供论文预处理小节直接引用
    experiments.md            # 实验设计、参数、指标与结果
    decisions.md              # 关键取舍、失败尝试及原因
    handoff.md                # 给论文写作者的可直接引用信息
```

如果某道题很小，可以合并文件，但不得省略下面的必填信息。代码和大数据文件放在 `src/`、`data/`、`result/` 等其既定目录；`docs/` 只保存说明、索引、元数据和必要的小型表格，不复制大型数据或生成物。

## 建模前必须记录

在 `README.md` 或 `assumptions.md` 中记录：

1. **题目与范围**：原题文件/页码、当前处理的子问题、输入和输出、未处理部分。
2. **问题类型**：预测、分类、优化、评价、仿真、图论、微分方程、时间序列、机器学习或组合模型；若为混合模型，说明各模块的输入输出关系。
3. **符号表**：符号、含义、数据类型/维度、单位、索引范围和来源。
4. **假设表**：假设内容、理由、影响对象、可检验方式和失效边界。假设必须编号，如 `A1`、`A2`。
5. **目标与约束**：目标函数是最大化还是最小化，约束的数学形式、边界、惩罚项和优先级。

## 数据记录要求

在 `data-dictionary.md` 中为每个实际使用的数据集和字段建立记录。至少包含：

| 字段 | 必须记录的内容 |
|---|---|
| 数据集 ID | 稳定名称和版本，例如 `D01-v2` |
| 来源 | 题目附件、文件路径、表名/页码、外部链接或采集设备 |
| 时间信息 | 采集/生成时间、时间区间、时区、采样频率或时间步长 |
| 字段定义 | 字段名、中文含义、数据类型、维度、允许范围 |
| 单位 | 原始单位、转换后单位、转换公式和换算系数 |
| 质量 | 样本数、缺失数、重复数、异常数、缺失机制判断 |
| 处理 | 清洗、去重、插值、归一化、标准化、降采样、特征工程 |
| 划分 | 训练/验证/测试或滚动窗口的规则，是否按时间或主体隔离 |
| 校验 | 范围检查、守恒关系、交叉字段一致性和人工抽查结果 |

对每个派生变量记录：

```text
变量 ID：Xxx
计算式：……
输入：……
输出单位：……
处理顺序：……
代码位置：src/...:行号或函数名
数据版本：Dxx-vx
```

禁止只写“进行了预处理”“数据已标准化”这类不可复现描述。标准化、归一化、角度转换、坐标转换和货币/时间换算都必须写出具体公式或系数。

## 数据处理规则记录要求

数据处理规则单独记录在 `data_procee.md` 中，并按**可能写入论文**的标准编写：论文写作者应能仅凭该文件改写出论文的数据预处理小节，因此措辞必须自足，不依赖对话上下文或口头约定。每条规则至少包含：

```text
规则 ID：P01、P02（按实际执行顺序编号）
适用数据集/字段：Dxx-vx 的哪些字段
动机：该规则对应的数据质量问题或题目要求（区分事实、假设与主观选择）
操作定义：具体公式、参数、阈值与作用方向
输入/输出：处理前后字段、单位、样本量或分布的变化
验证：抽查方式、抽查结果或合理性检查
```

规则按实际执行顺序排列，覆盖从原始附件到建模输入的完整链路；`data-dictionary.md` 的“处理”栏只写规则 ID 引用，不得与 `data_procee.md` 矛盾。废弃某条规则时保留编号并在文中标注停用原因，不得删除。

## 公式与模型记录要求

在 `model.md` 中按模型版本记录，不要覆盖旧版本。每个公式使用稳定编号，例如 `M1-EQ01`、`M1-EQ02`。每个公式至少包含：

```markdown
### M1-EQ01 目标函数

$$ ... $$

- 方向：最小化/最大化
- 变量：逐一解释符号、索引、维度和单位
- 参数：数值、单位、来源或估计方法
- 约束/适用条件：……
- 数学含义：……
- 代码实现：`src/...` 的函数/配置
- 版本变更：相对上一版改了什么、为什么改
```

额外要求：

- 公式中的每个量都必须能在符号表或数据字典中找到。
- 目标函数、约束、损失函数、评价指标和后处理规则分开编写。
- 概率、权重、评分和指数等无量纲量明确标注；不要把百分比和小数混用。
- 迭代算法记录初始化、停止条件、容差、最大迭代次数、随机种子和收敛判据。
- 机器学习模型记录输入形状、标签定义、网络/算法结构、损失、优化器、学习率、批大小、轮数、早停规则和硬件环境。
- 拟合或估计参数记录估计数据、估计方法、置信区间/误差（如有）和是否固定。
- 多模块模型必须画出或文字说明数据流：输入 → 预处理 → 子模型 → 融合/优化 → 输出。

## 编码求解与实验记录

在 `experiments.md` 中每次重要运行建立一条不可变记录，至少包括：

```text
实验 ID：EXP-YYYYMMDD-序号
对应模型：M1-vx
数据版本：Dxx-vx
代码版本：提交号/文件哈希
运行入口：命令、脚本或函数
环境：语言版本、关键依赖版本、操作系统、CPU/GPU（必要时）
随机性：随机种子及随机源
参数：完整配置文件或关键参数表
输出：结果文件、图表、日志路径
指标：名称、公式、单位、数值
耗时与资源：运行时间、内存/显存（可得时）
结论：本实验支持或否定的具体判断
```

实验对比应优先记录基线、消融、敏感性、误差分析和边界案例。每个指标写清计算公式、正负方向、聚合方式和单位；例如均方根误差不能只写 `RMSE=...`，还要说明是在何种样本集合、何种尺度上计算。

失败实验也要记录在 `decisions.md`：尝试的方法、输入与参数、失败表现、诊断、是否影响最终结论。不要删除失败记录，以免后续论文误把未验证方案写成已采用方案。

## 结果与论文交接

在 `handoff.md` 中只保留对论文写作有证据价值的内容：

- 问题定义、关键假设和模型公式编号；
- 数据来源、样本量、字段和单位；
- 数据处理规则编号清单（对应 `data_procee.md`），可直接改写为论文的数据预处理小节；
- 参数估计或选择依据；
- 主要结果及对应实验 ID、图表/表格路径；
- 与基线或替代模型的可比结果；
- 稳健性、敏感性、误差和适用边界；
- 不能支持的结论、已知局限和待补实验。

论文写作者应能仅凭 `handoff.md` 回到 `model.md`、`data-dictionary.md`、`experiments.md` 和代码位置。图表文件名应包含题目/实验/版本信息，图表旁记录数据来源、单位、筛选条件和绘图脚本。

## 变更与审查

- 修改公式、数据处理、单位、参数、训练划分或评价指标时，必须增加版本号并在 `decisions.md` 说明原因。
- 任何“最终结果”必须指向一个明确的 `EXP-*` 实验，不得只保留手工复制的数字。
- 提交前检查：公式可渲染；符号均有定义；单位闭合；数据来源可追溯；代码入口存在；结果文件可打开；随机种子和版本已记录；结论没有超出证据。
- 若题目新增或减少子问题，只新增或调整对应 `problem-XX/`，不要修改本文件以适应固定题量。
